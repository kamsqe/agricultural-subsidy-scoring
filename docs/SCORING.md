# Scoring Model: Impact Score

Формульный (не black-box) скоринг для ранжирования заявок на субсидии по потенциальному эффекту.

**Реализация:** `pipeline/score.py`

---

## Почему НЕ «предсказание отказа»

### Ceiling effect

Information Gain анализ 36,651 заявок:

| Признак | Information Gain | Cumulative |
|---|---|---|
| district | 0.058 bits | 0.058 |
| oblast | 0.041 bits | 0.099 |
| subsidy_code | 0.032 bits | 0.131 |
| month | 0.007 bits | 0.138 |
| **Всё остальное** | <0.005 bits | — |

Все видимые признаки объясняют ~31% rejection variance. Остальные 69% — качество документов, автоматические проверки ГИСС, решения инспектора. **Предсказать отказ невозможно** на доступных данных.

### Альтернатива: Impact Scoring

Вместо предсказания «кого отклонят», ранжируем одобренных по потенциальному эффекту:

| Пул | Количество | Что делаем |
|---|---|---|
| Исполнена + Одобрена | 28,627 | Ретроспективный анализ |
| Сформировано поручение | 2,854 | **Главный use case:** кого финансировать первым? |
| Отклонена | 2,909 | Анализ для Pre-Check |

## Pre-Check (Rule-Based, будущая функция)

Проверка заявки **до подачи** по формальным критериям Приложения 2.

| Тип субсидии | Код | Обязательные проверки |
|---|---|---|
| Покупка КРС | 00400 | БИН + ИСЖ + возраст + земля |
| Покупка быков | 00700 | БИН + ИБСПР + племенное свидетельство |
| Молоко | 02000 | БИН + ветсправка + договор с переработчиком |
| Селекция | 01300 | БИН + ИБСПР + план селекции |
| Корма (ЧС) | 04000 | БИН + акт о ЧС |

Потенциальный эффект: 30% заявок — повторные подачи. Pre-Check мог бы снизить их до ~10%.

## Impact Score: Формула

```
Score = 0.20×Strategic + 0.20×Fairness + 0.20×Need + 0.20×Efficiency + 0.10×Base − 0.10×Fraud + Exception
```

Каждый компонент ∈ [0, 100]. Base = 50. Fraud вычитается. Exception Points [0-15] — бонус за особые обстоятельства.
Triage bands: **A** (≥65, высокий приоритет), **B** (55-64, стандартный), **C** (40-54, низкий), **D** (<40, отклонение).

### Компонент 1: Strategic Alignment (0-100)

Соответствие приоритетам АПК и региональной специализации.

| Фактор | Max баллов | Источник данных |
|---|---|---|
| Региональная специализация | 40 | stat.gov.kz: поголовье скота по регионам (34 признака) |
| Приоритетный код субсидии | 30 | Концепция АПК 2021-2030: коды 01200, 01300, 02000, 04500 |
| Продовольственная безопасность | 30 | Самообеспеченность КЗ: птица 58%, молоко 89%, говядина 82% |

### Компонент 2: Fairness Factor (0-100)

Справедливость распределения, антимонопольный механизм.

| Фактор | Max баллов | Логика |
|---|---|---|
| Монополизация района | 40 | `district_top1_share` > 0.5 + мелкая заявка = бонус |
| Размер vs медиана | 30 | Около медианы = max, далеко выше = штраф |
| Бонус мелкого фермера | 30 | < 1 млн ₸ = 30, < 5 млн = 22, < 20 млн = 12 |

### Компонент 3: Regional Need (0-100)

Бюджетный дефицит и потребность региона.

| Фактор | Max баллов | Источник данных |
|---|---|---|
| Backlog ratio области | 30 | Из основного датасета: доля «Сформировано поручение» |
| Внешняя воронка одобрения | 25 | plem.kz API: `oblast_approval_rate` (436 записей) |
| Бюджет на заявителя | 25 | plem.kz API: `budget_per_applicant` (18 областей) |
| Сезонность | 20 | Март-апрель = max, август = min |

### Компонент 4: Efficiency Potential (0-100)

Вероятность эффективного использования субсидии.

| Фактор | Max баллов | Логика |
|---|---|---|
| Retry-история | 35 | 1 retry = max (упорный), 0 = хорошо, >3 = подозрительно |
| Репутация района | 40 | `(1 - district_reject_rate) × 40` |
| Разумность суммы | 25 | 0.3-2.0× от медианы района = max |

### Компонент 5: Fraud Risk (0-100, вычитается)

| Фактор | Max баллов | Что проверяем |
|---|---|---|
| Круглые суммы | 15 | Кратность 1 млн / 100K ₸ |
| Экстремальный outlier | 25 | `amount_vs_median` > 10 |
| Избыточные retry | 20 | retry_count > 5 |
| Монопольный район | 15 | `district_top1_share` > 0.7 |
| Ночная подача | 10 | 00:00 — 05:00 |

> **Удалено:** «Выходная подача» (was +8) — анализ данных показал δ=+0.2pp reject rate (8.1% vs 7.9%), что является шумом.

Флаги: `high_fraud_risk` (>50), `requires_audit` (>70).

### Компонент 6: Exception Points (0-15, бонус)

Инспирирован UNOS exception points (трансплантология) — бонус за особые обстоятельства.

| Фактор | Баллы | Условие |
|---|---|---|
| Первая подача | +5 | retry_count = 0 |
| Область с высоким бэклогом | +5 | oblast_backlog_ratio > 0.30 |
| Мелкий фермер в монопольном районе | +5 | amount < 5M ₸ AND district_top1_share > 0.4 |

Результат: 25,649 заявок получили «первая подача», 4,386 — «высокий бэклог», 456 — «мелкий фермер в монополии».

### Fraud-анализ

- **7 заявок** (0.02%) с высоким fraud-риском (>50)
- **0 заявок** с критическим fraud-риском (>70)
- Типичные fraud-факторы: экстремальные outlier-суммы + круглые числа + ночная подача
- Снижение с 14 до 7 после удаления «выходная подача» — те 7 имели другие реальные аномалии

### FIFO vs Merit-based (ключевой результат)

Симуляция на 2,854 заявках в статусе «Сформировано поручение», бюджет на 50%:

| Метрика | FIFO | Merit | Delta |
|---|---|---|---|
| Средний балл | 63.5 | 67.9 | **+4.4** |
| Мелких фермеров | 1,232 | 1,340 | **+108** |

Merit-based подход финансирует больше мелких фермеров с более высоким средним Impact Score.

### Retry-анализ

- 30% заявок — повторные подачи (11,002)
- Avg score (первая подача): **63.4**
- Avg score (повторная): **58.0** (−5.4, объясняется exception points для первых подач)

### Gini coefficient

Текущий Gini по районам: **0.648** (высокое неравенство в распределении бюджета).

### Percentile Ranking

Каждая заявка получает percentile rank: «лучше чем X% заявок». Реализовано в pipeline и PreCheck.

## Explainability

Три уровня объяснений (в соответствии с требованием ТЗ):

### Уровень 1: Summary (для комиссии)

```json
{
  "score": 69.8,
  "rank": 1,
  "components": {"strategic": 83, "fairness": 80, "need": 62, "efficiency": 100, "fraud_risk": 0},
  "explanation": "Высокий балл: племенной тип + мелкий фермер + нет аномалий"
}
```

### Уровень 2: Component breakdown (для аналитика)

Каждый компонент раскладывается на факторы. Пример для Strategic Alignment = 83:
- Региональная специализация: 38/40 (обл. Абай, высокое поголовье КРС)
- Приоритетный код: 30/30 (код 01300 — селекция)
- Продовольственная безопасность: 15/30 (КРС — средний приоритет)

### Уровень 3: Counterfactual (для фермера)

«Что бы изменилось, если...»:
- Подать в марте вместо августа → +4 балла (сезонный фактор)
- Перейти на племенное направление → +6 баллов (стратегический приоритет)
- Подать с суммой < 5 млн ₸ в монополизированном районе → +5 exception points

## Pre-Check: Анализ причин отказа (plem.kz 2021-2024)

**Источник:** Реестры заявок subsidy.plem.kz за 2021 и 2024 год (99,200 записей, 6,811 отклонённых).

Поле `Solution` содержит свободный текст причины отказа. Мы проанализировали **5,748 причин** и категоризировали их:

| Категория | Кол-во | % | Описание |
|---|---|---|---|
| Проблемы с платежными документами | 2,361 | 24.3% | Отсутствие ЭСФ, платёжных поручений, банковских выписок |
| Несоответствие данных в документах | 1,438 | 14.8% | Расхождения между документами и заявкой |
| Расхождение объёмов/количества | 1,027 | 10.6% | Объём в заявке ≠ объём в ЭСФ/актах |
| Проблемы с договорами/актами | 866 | 8.9% | Неполный договор, отсутствие приложений |
| Несоответствие критериям субсидии | 828 | 8.5% | Не выполнены обязательные условия Приложения 2 |
| Отсутствие документов | 659 | 6.8% | Документы не загружены в систему |
| Проблемы с регистрацией | 542 | 5.6% | Проблемы с БИН, кооперативом, регистрацией |
| Идентификация животных | 383 | 3.9% | Несоответствие ИНЖ, отсутствие в ИСЖ/ИБСПР |
| Исчерпание бюджета | 20 | 0.2% | Отказ по Пункту 21 (бюджет исчерпан) |

**Ключевой вывод:** 83.6% отказов связаны с **документами** (качество, полнота, соответствие). Это подтверждает ceiling effect — причины отказа невидимы в нашем основном датасете.

**Реализация:** `data/external/analyze_rejections.py` → `data/processed/rejection_reasons.json`
**В UI:** PreCheck показывает распределение причин отказа для выбранного типа субсидии + чеклист.

## Sensitivity Analysis

Пертурбация каждого веса на ±0.05 (±25% относительно) и измерение влияния на 36,651 заявок:

| Компонент | Δ Weight | Mean Score Δ | Avg Rank Change | Max Rank Change |
|-----------|----------|-------------|-----------------|-----------------|
| **Strategic** | +0.05 | +3.46 | 780 | 4,688 |
| **Strategic** | −0.05 | −3.45 | 855 | 4,688 |
| **Fairness** | +0.05 | +3.41 | 649 | 4,361 |
| **Fairness** | −0.05 | −3.40 | 755 | 4,361 |
| **Need** | +0.05 | +2.33 | 608 | 3,897 |
| **Need** | −0.05 | −2.32 | 647 | 3,897 |
| **Efficiency** | +0.05 | +4.25 | 613 | 3,512 |
| **Efficiency** | −0.05 | −4.24 | 696 | 3,512 |
| **Fraud** | +0.05 | −0.33 | 512 | 2,891 |
| **Fraud** | −0.05 | +0.33 | 614 | 2,891 |

**Выводы:**
- Efficiency — самый чувствительный компонент (±4.25 на средний балл)
- Fraud — наименее чувствительный (±0.33), что ожидаемо при 10% весе
- Ни один компонент не доминирует настолько, чтобы обнулить остальные
- При ±25% сдвиге средний ранг меняется на ~600-850 позиций из 36,651

**Реализация:** `pipeline/score.py::run_sensitivity_analysis()`

## Ограничения (честно)

| Ограничение | Влияние | Митигация |
|---|---|---|
| **69% variance unexplained** | Модель видит только 31% причин отказа | Impact scoring вместо prediction |
| **Веса = экспертная оценка** | Не калиброваны на A/B тесте | Sensitivity analysis проведён (см. ниже) + прозрачные формулы |
| **Нет farmer ID** | Proxy (район + тип + сумма) для retry | Точность не измерена; возможны false positives при совпадении района/типа/суммы у разных заявителей |
| **Нет данных о результатах** | Не знаем ROI субсидии | Используем proxy: одобрение + исполнение |
| **Gaming** | Заявки можно подстраивать под формулу | Регулярное обновление весов |

### Что нужно для production

1. Калибровка весов на исторических данных (plem.kz 2019-2024)
2. A/B тест в одном районе
3. Интеграция с ПКБ/ИСЖ для реальных финансовых и производственных данных
4. Регулярный мониторинг fraud false-positive rate

## Проактивный Анализ Фермера

Модуль, переворачивающий модель: вместо ожидания заявки от фермера, система анализирует профиль хозяйства и рекомендует подходящие субсидии.

**Реализация:** `agroscore/src/components/ProactiveFinder.tsx`

### Архитектура

```
PreCheck:    "Подойдёт ли ЭТА заявка?"      (1 субсидия, пользователь выбирает)
Проактивный: "Что СТОИТ подать фермеру?"     (все 40 субсидий, система выбирает)
```

Проактивный модуль = PreCheck × 40 + Анализ Мощностей. Reuses тот же Impact Score.

### Профиль фермера

200 синтетических профилей (`agroscore/public/data/farmer_profiles.json`), сгенерированных `generate_profiles.py`. Поля соответствуют реальным системам:

| Поле | Источник в production |
|------|----------------------|
| Поголовье по видам | ИСЖ (Информационная система животноводства) |
| Земля, пастбища | ЕГКН (Единый государственный кадастр) |
| Кредитная история | ПКБ (Первое кредитное бюро) |
| Суточный надой, падёж | ARM фермера |
| История субсидий | ГИСС |

### Агронормы

`agroscore/public/data/agro_norms.json` — реальные нормативы:

| Норма | Значение |
|-------|---------|
| Пастбищная нагрузка КРС | 3.0 га/голова (степь 4.0, орошаемые 1.8) |
| Пастбищная нагрузка МРС | 0.5 га/голова |
| Падёж КРС (норма) | 3% |
| Падёж МРС (норма) | 5% |
| Мин. обеспеченность помещениями | 80% |
| Корма на зиму (КРС) | 3.0 т/голову |

### Eligibility Engine

40 кодов субсидий → 22 кластера по типу:

| Кластер | Коды | Требования |
|---------|------|-----------|
| Покупка КРС | 00100-00400, 02200 | КРС > 0, земля > КРС × 3 га |
| Племенные быки | 00700 | КРС > 10 |
| Селекция | 01200, 01300 | Поголовье > 50, кредит ≠ poor |
| Молоко | 01700-02000 | Дойные > 5, надой > 20 л, доильное оборудование |
| Корма | 04000, 04500, 04800 | Поголовье > 10, хранение кормов > 1 т |
| Овцы/козы | 03100, 03900, 11600 | Овцы > 0 |
| Птица | 05401-05901 | Птица > 500 |

Для каждой подходящей субсидии:
1. **Capacity headroom** = свободные пастбища / га на голову
2. **Recommended volume** = min(capacity, median для типа)
3. **Estimated amount** = volume × norm
4. **Impact Score** = через `calculateScore()` из `scoringEngine.ts`
5. **Warnings** = перегрузка пастбищ, падёж, инфраструктура

### Интерфейс специалиста УСХ (v2)

Проактивный модуль предоставляет специалисту Управления сельского хозяйства рабочий интерфейс:

#### Фильтрация по области

Dropdown с 18 областями + счётчик профилей. Позволяет специалисту работать со своим регионом.

#### Действия по каждой рекомендации

| Действие | Статус | Цвет | Значение |
|----------|--------|------|---------|
| (по умолчанию) | Новый | серый | Ещё не обработан |
| Пригласить к подаче | Приглашён | зелёный | Специалист решил пригласить фермера |
| Отклонить | Отклонён | красный | Специалист решил не приглашать |
| Сбросить | Новый | серый | Вернуть в исходное состояние |

**Состояние хранится в памяти браузера** — это prototype без backend. В production нужна БД.

Счётчики действий отображаются в верхней панели (✉ приглашённых, ✕ отклонённых).

#### Панель методологии

Раскрывающаяся секция "Как работает?" с:
- **Источники данных:** ИСЖ, ЕГКН, ПКБ (помечены как синтетические), stat.gov.kz, plem.kz (помечены как реальные)
- **Движок:** 4-шаговый flow (Профиль → Мощности → Eligibility → Impact Score)
- **Прозрачность:** пометка "production note" о замене данных на API

#### Per-card Explainability

Каждая карточка рекомендации раскрывается ("Почему рекомендуем?") и показывает:
1. **Matched fields** — какие поля профиля совпали с требованиями кластера (зелёные галочки)
2. **Impact Score breakdown** — 5 компонентов в виде progress bars:
   - Strategic Alignment
   - Fairness Factor
   - Regional Need
   - Efficiency Potential
   - Fraud Risk

### Данные проактивного модуля (провенанс)

| Компонент | Файл | Тип данных |
|-----------|------|-----------|
| Профили фермеров | `farmer_profiles.json` | **Синтетический** (200 шт., распределения из stat.gov.kz) |
| Агронормы | `agro_norms.json` | **Реальные значения**, наша JSON-структура |
| Коды субсидий | `subsidy_codes.json` | **Вычислен** из реального датасета |
| Агрегаты районов | `districts.json` | **Вычислен** из реального датасета |
| Scoring Engine | `scoringEngine.ts` | **Та же формула**, что и pipeline/score.py |

### Production-готовность

```
Прототип:  farmer_profiles.json → Eligibility Engine → Impact Score → UI
Production: ИСЖ + ЕГКН + ПКБ API → (тот же движок) → (тот же UI)
```

Замена синтетических данных на API — конфигурационное изменение, не переписывание.
