## 6 идей (детально)

### MUST #1: Ансамбль моделей (Simpson's Paradox)

**Что это:** Отдельные модели для каждой категории субсидий вместо одной общей.

**Почему важно:**
```
Гипотеза: "Крупные хозяйства отклоняют чаще"

Общий датасет:
  Крупные: 12.1% reject
  Мелкие:  8.3% reject
  → Вывод: да, крупных отклоняют чаще

Контроль по типу:
  Покупка КРС: Крупные 18.2% > Мелкие 11.4%  ✓
  Молоко:      Крупные 6.1%  < Мелкие 9.8%   ✗
  Селекция:    Крупные 0.9%  ≈ Мелкие 0.7%   —

→ Одна модель даёт ЛОЖНЫЙ паттерн!
```

**Как демонстрируем:**
1. Показываем таблицу с парадоксом
2. Объясняем почему одна модель врёт
3. Показываем ансамбль (4 модели по категориям)

**Фраза для жюри:**
> "Другие команды скорят одной моделью. Мы доказали Simpson's paradox на данных — и построили ансамбль. Это не усложнение ради усложнения, это необходимость."

### MUST #2: Case-level дедупликация (Paradigm Shift)

**Что это:** Переход от анализа заявок к анализу кейсов (уникальная потребность: фермер + тип + сумма). В обезличенном датасете мы вычисляем фермера через прокси: `producer_id = app_num[:11]`.

**Доказательство (на реальных данных):**
Из 36,651 заявки мы выделили 2,908 уникальных производителей. Разбив их заявки по типам и суммам, мы получили 23,851 уникальный кейс (намерение получить субсидию). Это доказывает, что более трети всех заявок в датасете — это технические дубли и повторные подачи.

**Почему важно:**
```
Application-level:
  36,651 заявок
  2,909 отказов
  Reject rate = 9.2%

Case-level:
  23,851 уникальных кейсов
  881 отказов (кейсы, которые никогда не были одобрены)
  Reject rate = 3.7%

Разница: 2,028 отказов = RETRY одного и того же кейса
```

**Инсайт:**
- 65% отказов — не "плохие фермеры", а повторные подачи
- Проблема не в отборе, а в **friction** (фермер не знает причину до подачи)
- Решение: Pre-Check система

**Как демонстрируем:**
1. Показываем два числа: 9.2% vs 3.7%
2. Объясняем откуда разница
3. Показываем примеры retry (один фермер, 5 заявок)

**Фраза для жюри:**
> "На первый взгляд — 9.2% отказов. Мы копнули глубже и обнаружили: 65% отказов — это один и тот же фермер, который подаёт снова и снова. Реальный reject — 3.7%. Проблема не в том, КОГО отклоняют, а в том, что фермер не знает причину ДО подачи."

**Фраза для жюри:**
> "Каждый отказ — это не тупик, а план действий. Фермер видит конкретные шаги для улучшения своего рейтинга."

### SHOULD #5: Pre-Check (превентивный скоринг)

**Что это:** Проверка заявки ДО подачи по правилам Приложения 2.

**Проблема:**
```
Текущий процесс:
1. Фермер подаёт заявку
2. Ждёт 2 дня
3. Получает отказ "Несоответствие критериям"
4. Не понимает что не так
5. Исправляет наугад
6. Подаёт снова
7. Повторяет 3-5 раз

Результат: 65% отказов = retry
```

**Решение:**
```
С Pre-Check:
1. Фермер заполняет форму
2. СРАЗУ видит:
   ❌ Скот не зарегистрирован в ИСЖ
      → Зарегистрируйте на isj.gov.kz
   ❌ Возраст скота 24 мес. (норма 4-18)
      → Субсидия только для молодняка
   ✓ БИН/ИИН валиден
   ✓ Земля есть
3. Исправляет ДО подачи
4. Подаёт 1 раз
```

**Ожидаемый эффект:**

| Метрика | Сейчас | С Pre-Check | Улучшение |
|---|---|---|---|
| Retry rate | 65% | 15% | -77% |
| Avg attempts | 2.3 | 1.2 | -48% |
| Inspector workload | 36,651 | ~25,000 | -32% |
| Farmer frustration | High | Low | ↓↓↓ |

**Фраза для жюри:**
> "65% отказов — это retry. Фермер не знает причину до подачи. Наш Pre-Check показывает проблемы СРАЗУ. Один клик — и фермер видит что исправить."

### MUST #6: Честный AI (Три слоя)

**Что это:** Интеграция AI без бутафории. Мы не используем ML для предсказания "нарисованного" таргета, а используем ИИ там, где он даёт реальную ценность.

**Три слоя AI в AgroScore:**

| Слой | Роль | Технология | Ценность для жюри |
|---|---|---|---|
| **1. Вычислительный ML** | Инсайты из данных | Clustering (K-Means), Anomaly Detection (Isolation Forest) | "Мы нашли 5 поведенческих кластеров фермеров и ловим признаки Fraud" |
| **2. Интеллектуальный NL** | Объяснение решений | LLM-генерация текста (GPT/Claude) | "Комиссия и фермер получают текстовое объяснение на естественном языке, почему скор именно такой" |
| **3. Интерфейс (MCP)** | Интеграция с агентами | Model Context Protocol Server | "Наша система открыта для ИИ-агентов министерства, они могут общаться с ядром скоринга напрямик" |

**Фраза для жюри:**
> "Вместо того чтобы обучать ML-модель предсказывать саму себя (из-за отсутствия ground truth), мы сделали честный AI. Наш ML находит аномалии и кластеры, а LLM — переводит сложные баллы в понятные текстовые объяснения для фермера на двух языках. И наша архитектура нативно поддерживает MCP для ИИ-агентов. Это честное и эффективное применение."

**Что это:** Оценка соответствия заявки официальным целям Концепции АПК 2021-2030.

**Почему важно:**
- Субсидии должны решать конкретные задачи (продбезопасность, модернизация)

- Мелкие фермеры = социальная миссия

**Компоненты:**

| Фактор | Вес | Что измеряет |
|---|---|---|
| Food Security Priority | 25% | Приоритет продбезопасности |
| Small Farmer Bonus | 20% | Поддержка мелких (Rawlsian fairness) |
| Underserved Region | 20% | Недофинансированные регионы |
| Productivity Potential | 20% | Потенциал роста |
